## What this program is

Smart Parks Protect Go reads the SD card of a RangerEdge offload station where there is no connection, decodes the trackers' frames with Protect's own code, shows the result, and hands the untouched card files to Protect when there is a connection. Protect is the source of truth; Protect Go is a reader with a queue. The reasoning is ADR 0001 in `docs/adr/`.

## Relationship to Protect

- **One decoder.** `pyproject.toml` depends on `smartparks-protect-shared` from Protect's repository, subdirectory `shared`, pinned to a commit under `[tool.uv.sources]`. `scripts/dev.sh bump-protect [rev]` moves the pin, relocks and reruns `tests/test_protect_decoding.py`, which unwraps the firmware's LP0 fixture with Protect's codec and loads the OpenCollar driver. Record a bump in `CHANGELOG.md` and in the status line above.
- **Modules Protect Go may import from `shared`:** `shared.station_decode` (the one decode path of a station frame: `unwrap_station_frame` with its refusals, `decode_station_frame`; Protect's phase 43 P6), `shared.connectivity.adapters.lp0_station` (the LP0 codec and adapter), `shared.device_drivers` (the drivers and their base), `shared.connectivity.base`, `shared.enums`, `shared.timeutil`, `shared.geodesy`, and `shared.station_files` (the station file parser, split out for Protect Go by Protect's phase 43 P1). **Never:** `shared.config` (wants a database URL and a broker), `shared.bus`, `shared.models`, `shared.database`, `shared.storage`, `shared.trace`'s database half, `shared.domain.*`. The tests run without `DATABASE_URL`, `REDIS_URL`, `MINIO_ENDPOINT` or `JWT_SECRET` and one test asserts none is set; CI sets none.
- **What Protect provides** (planned there, see the contract in `docs/contract.md`): the field bundle endpoint and the map extract; the card upload is Protect's existing log files endpoint.
- **Conventions, tooling and documents** are copied from Protect: `CONVENTIONS.md`, `CODE_OF_CONDUCT.md`, the git hooks, the ruff and mypy configuration, the CI shape, Dependabot, the MkDocs site, the frontend's configuration and its shadcn components. Protect's copies are the master. When Protect changes one, copy the change here.

### Differences from Protect

- One Python package (`protect_go`) instead of a uv workspace; `src = ["."]` for ruff.
- No database server: the local store (phase 2) is SQLite, through SQLAlchemy since `shared` brings it.
- No authentication: the program runs on one person's computer and listens on 127.0.0.1. The bundle on disk is encrypted with a key in the laptop's keychain, or a key file where there is none (decision D11).
- Settings carry the prefix `PROTECT_GO_` (`protect_go/config.py`, `.env.example`).
- The pre-commit hook has no Ansible paths and refuses the `data/` folder and a LoRaWAN session key given a value in code, with the firmware's synthetic fixture allowed.
- The docs check has no MCP half. The documentation site is published from `main` by the pages job, as Protect's is, at https://smartparksorg.github.io/smartparks-protect-go/.
- CI has no services, no OpenAPI drift job yet (comes with the first API the frontend types against) and no compose job.

## Packaging, after AddaxAI (decision D6)

The desktop AddaxAI ships an Electron shell with a PyInstaller-frozen Python backend as `extraResources`, built by electron-builder into an NSIS installer (`-Setup.exe`, per user, no administrator), a dmg (drag to Applications) and a deb, attached to a GitHub release by a workflow that runs when the release is published, the version copied from the tag into `VERSION` and `electron/package.json`. Its website links `releases/latest/download/<fixed name>` per system, and the app checks GitHub's releases list at start and shows a notice; the user installs the new installer over the old one, which keeps the data folder outside the install folder. Protect Go does the same:

- `electron/src/main.ts`: one instance; `protect-go://connect?server=…&code=…` from a second instance or macOS's `open-url` becomes the route `/setup?server=…&code=…` (decisions D9 and D15; the code is passed only when it is 16 to 128 URL-safe characters); the backend is `process.resourcesPath/backend/backend(.exe)` when packaged, else the repository's `.venv` python with `-m protect_go`; `PROTECT_GO_PORT`, `PROTECT_GO_DATA_DIR` (`~/ProtectGo`) and `PROTECT_GO_HOST` passed in the environment; the backend's output goes to the console and `logs/backend.log` in the data folder; a Protect Go backend of this version already answering on the port is used; one of another version is stopped first (decision D20: `POST /api/shutdown`, then the listener on the port killed through `netstat -ano` and `taskkill` on Windows or `lsof` elsewhere; an installer that closed the old window left the old backend running, and the new window used it with the old interface), a stranger on it is an error with the way out named; the window's cache is emptied (`session.defaultSession.clearCache()`) and it loads `http://127.0.0.1:18090` (decision D23: after an update the window showed the old pages from Chromium's heuristic cache; the backend also serves the interface with `Cache-Control: no-cache`, the hashed assets aside), web links open in the system browser, the window never navigates away; the menu has Check for updates (sent to the page as `menu:command`), Documentation, Open the data folder. Full screen (Tim, 2026-10-17, on Windows: the menu bar disappears with it and so did the way out): `before-input-event` toggles on F11 and leaves on Escape whatever the menu does, `enter-full-screen` and `leave-full-screen` are sent to the page as `window:fullscreen`, and `components/FullScreenNotice.tsx` shows a pill at the top centre (the top right holds the connection dot) with the key and a Leave button (`window:leaveFullScreen`), fading after 4 s and back when the pointer touches the top edge. `preload.ts` exposes `window.protectGo` (version, platform, openExternal, onMenuCommand, pickFolder, leaveFullScreen, onFullScreen, updateStatus, checkForUpdates, downloadUpdate, installUpdate, onUpdateStatus). The self-update (decision D17): `electron-updater` with the GitHub provider (`build.publish` in `electron/package.json`; electron-builder writes `latest.yml` and the blockmap, the workflow attaches them to the release beside `ProtectGo-Setup.exe`); on Windows in a packaged app only (`UPDATES_SUPPORTED`), `autoDownload` off and `autoInstallOnAppQuit` on, a check 8 s after start and from the menu, the state (`idle`, `checking`, `none`, `available`, `downloading` with a percentage, `downloaded`, `error`) sent to the page as `update:status`; `update:download` checks first when nothing is known; `update:install` stops the backend (its files are in the install folder) and calls `quitAndInstall(false, true)`: not silent, so the installer's window with its progress bar is on the screen while the files change (decision D22); `build/installer.nsh` makes that window close by itself once the files are in (`SetAutoClose` in `customInstall` when `isUpdated`) and skips the finish page while starting the app (`customFinishPage`), so no click is needed and nothing goes dark between the steps; electron-builder already skips the license and directory pages of an update. A download that installs on quit stays silent. An unsigned build carries `unsignedBuild: true` in its package.json (the workflow's `-c.extraMetadata.unsignedBuild=true` when no certificate is present) and the shell then sets `verifyUpdateCodeSignature` to accept the download: electron-updater otherwise demands the publisher's signature (`signtoolOptions.publisherName`) on the downloaded installer, which an unsigned installer does not carry (Tim, 2026-10-17: "not signed by the application owner"). A signed build keeps the check. The notice draws the download as a progress bar. Where the app cannot update itself, or the update failed, the notice offers this computer's installer from `releases/latest/download/` (`installerFor(platform)` in `hooks/useLatestRelease.ts`, the platform from the shell or the user agent) and the list of all releases. macOS refuses updates to an unsigned app (Squirrel.Mac) and the deb has no updater, so the status is `unsupported` there and `components/UpdateNotice.tsx` keeps the download link; with the status present it shows Download and install, the progress, then Restart to update. Test: `UpdateNotice.test.tsx` with a bridge stub.
- `backend.spec`: entry `protect_go/__main__.py`, `datas` the built interface, `VERSION` and `uv.lock` (read through `sys._MEIPASS`, `version.py`), the OpenCollar driver's catalogue and codec files, `hiddenimports` for the decoding modules, `excludes` for the server-only packages `shared` depends on and Protect Go never imports (matplotlib, weasyprint, pyarrow, Pillow, openpyxl, chirpstack, grpc, minio, mqtt, asyncpg, psycopg). About 150 MB on Linux. `protect_go/decoding.py` imports the parser, the codec and the driver at start so a frozen build that lacks one fails at once, and `/api/health` names the decoders.
- `electron/package.json`'s `build`: appId `org.smartparks.protect.field`, product name Protect Go, artifacts `ProtectGo-Setup.exe`, `ProtectGo-arm64.dmg`, `ProtectGo-amd64.deb`, the `protect-go` scheme, NSIS not one-click with the directory changeable and `installer.nsh` (decision D24: an update or a silent uninstall never touches `~/ProtectGo`; a real uninstall asks "Keep your Protect Go data?" with Yes and the default both keeping it), hardened runtime and `notarize.js` after signing on macOS, the icon from `build/icon.png` (Protect's stacked Smart Parks logo, the mark with the name, in white on brand green with rounded corners, 1024 px, rendered from `services/frontend/src/assets/brand/logo-stacked.svg`; electron-builder derives the icns and ico).
- `.github/workflows/build-installers.yml`: on a pushed `v*` tag (decision D19: `prepare` makes a draft release when none exists, the three builds attach their files to it, `publish` checks the five names and takes the release out of draft, so neither the updater nor the download links ever see a release without its files), and by hand for debug builds kept 14 days. Windows signs when `WINDOWS_CERT_PFX_BASE64` and `WINDOWS_CERT_PFX_PASSWORD` are set, macOS signs and notarises when `MACOS_CERTIFICATE`, `MACOS_CERTIFICATE_PWD`, `APPLE_ID`, `APPLE_APP_SPECIFIC_PASSWORD` and `APPLE_TEAM_ID` are; without them the build warns and the installer is unsigned (`REQUIRE_SIGNING` in the workflow turns that into an error once the certificates exist; AddaxAI hard-fails, Protect Go cannot yet). Every build starts the frozen backend and checks that health names the decoders before packaging.
- Updates (decision D8): `hooks/useLatestRelease.ts` asks `api.github.com/repos/SmartParksOrg/smartparks-protect-go/releases?per_page=1` once per start (the newest release of any kind, so a pre-release counts), compares with `lib/version.ts`, and `UpdateNotice` shows the newer version with its notes and a button to the user page; the menu's Check for updates shows the result either way. A dev build (`v0.0.0-dev`) never nags. Automatic download and install (electron-updater) waits for signed builds.
- Releasing: write `VERSION`, close the changelog section and commit on `main`; make the draft release with the notes written for users (the notice shows them verbatim): `gh release create vX.Y.Z --draft --title "Protect Go vX.Y.Z" --notes-file notes.md`; then tag and push the tag. The workflow attaches the installers and publishes the release when every file is there (about 20 minutes). Never publish the release by hand before that: an installed app that checks in the meantime gets a 404 for `latest.yml`. The docs' download links point at `releases/latest/download/<name>`, so they never change.

## The bundles (decisions D2, D11, D31 and D32)

`protect_go/bundle.py`: `BundleStore` keeps a bundle per project (D31, Tim, 2026-10-24: after a second project was loaded the app said nowhere which one it used, the stations stood on the first project's tiles and the lists mixed both) under `bundles/<project id>.enc`, Fernet-encrypted, with the fetch time in the envelope, and names the loaded project in `bundles/current`; `save(bundle)` writes the project's file and makes it the loaded one, `switch(project_id)` makes another project on the laptop the loaded one without a connection, `load(project_id=None)` gives one back whole (the loaded one without an id), `summary()` the counts the pages show (never a key), stale after seven days, `summaries()` every project on the laptop by name, `clear()` removes one; the one `bundle.enc` of versions before is moved under its project at start (`_migrate_legacy`). The key comes from `protect_go/secrets.py`: the operating system's keychain through `keyring` (service "Smart Parks Protect Go"), made on first use; where no keychain answers (no backend, a locked keychain, a denied prompt, this WSL machine), a key file `bundle.key` in the data folder with mode 600; `PROTECT_GO_KEY_STORE=file` forces the file (the tests, a headless machine). `routers/common.py` `current_project_id(request)` is what every router asks first (D32): the lists, the explorer, the files, the uploads and the map answer the loaded project's and nothing of another. `routers/bundle.py`: `GET /api/bundle` (the loaded project), `GET /api/bundle/projects` (every project on the laptop with whether it is loaded, its map and its cards), `POST /api/bundle/switch {project_id}` (404 when the project is not on the laptop), `DELETE /api/bundle[?project_id]`, `POST /api/bundle/fetch {project_id, project_name}`, which fetches the bundle (401 when the sign-in expired, 502 with the server's words or when the bundle names another project, a shape other than `format_version` 1 refused), keeps it as the loaded project, adopts the cards of no project yet that its stations wrote (`CardStore.adopt_cards`, D32), reads the frames of trackers unknown before (D28), then calls the map fetch (with `ask_first` when the served bundle's `map.covers_areas` is false, decision D35: the server's map was cut for regions the project has outgrown, so `fetch_project_map` POSTs once before the GET and the 202 branch asks no second time) and returns both states with `frames_read_again` and `cards_adopted`; a load or a switch resets the follow-the-server state (`app.state.bundle_follow`) so the next probe syncs at once. The sync (D34, Tim, 2026-10-24: a switch should be a view change with nothing left to fetch): `_follow_the_projects` in `routers/setup.py` runs inside `GET /api/setup/connection`, and when the cycle is due (`REVISION_CHECK_EVERY`, five minutes) and no sync is running, starts `_sync_projects` as an `asyncio` task (`app.state.bundle_sync_task`; the tests await it) and answers the last state at once: the task lists the server's projects through `server_projects` (the route's own function, the station counts from the Offload overview), loads every project with a station that is not on the laptop (`load_bundle(app, body, make_current=False)`, which keeps the bundle beside the loaded one, `BundleStore.save(make_current=False)`), loads again a project whose revision moved, fetches a map that is missing, and writes `projects_synced_at`, `projects_loaded` and `projects_on_laptop` beside the loaded project's own `bundle_updated_at`, `frames_read_again` and `map_updated_at`; `load_bundle` and `fetch_project_map` take the app, not a request, so the task can call them. The shell invalidates the switcher's list, the map and the bundle when `projects_synced_at` moves. `components/layout/ProjectSwitcher.tsx` is the top bar's switcher (D33): the projects on the laptop switch at once, the server's projects with an offload station (online and signed in) are loaded when chosen, every query is invalidated after either and the page goes to the Overview; `LoadSection` on the Server page keeps the Load button and lists the laptop's projects with Use. `backend.spec` collects `keyring`'s backends so the frozen build finds the right one per system.

## A card read (decision D2, phase 2 F2)

`protect_go/volumes.py` (decision D16): `removable_volumes()` lists where a card can sit (Windows' drives of type `DRIVE_REMOVABLE` with their labels through `kernel32`, macOS's `/Volumes` but the boot volume, Linux's `/media` and `/run/media` mounts), `station_files_under(root)` finds `STATION_FILE` names three levels deep with system and hidden folders skipped and at most 2000 folders visited, `volumes()` describes each with its files, size and station EUIs, `read_files(root)` returns the files as a drop would carry them (`folder/name`, bytes). `GET /api/cards/volumes` (before `/cards/{card_id}` in the router, so the literal path wins) answers the volumes with the station names from the bundle; `POST /api/cards/path {path, name?}` reads a card from a path on this computer (404 no folder, 422 no station file, 409 no bundle). The shell's `dialog:pickFolder` (preload `pickFolder(title)`) opens the system's folder dialog; the Files page polls the volumes every 5 s while a bundle is loaded, reads one with a click, and uses the dialog for "Pick the card's folder" inside the shell, the browser's `webkitdirectory` input outside it. Test: `tests/test_volumes.py` lays a card out in a folder.

`protect_go/cards.py`: `CardStore` owns `field.db` (SQLite, WAL, foreign keys) with `cards`, `card_files`, `frames` and `records`. Every card carries the `project_id` of the bundle it was read with (D32), every read the pages make (`cards`, `files`, `stations`, `trackers`, `unknown_trackers`, `records`, `offered_metrics`, `positions`, `pending_files`, `upload_summary`, through `_scope`) takes the loaded project's id and answers that project's alone, `cards_per_project` counts them for the switcher, and `adopt_cards(bundle)` gives a card of no project yet (read before D32) to the project whose stations wrote it the first time that project is loaded or switched to. `import_card(name, files, bundle)` takes what was dropped as `(name, bytes)` pairs: a `.zip` goes through `unpack_card_zip`, a `.jsonl` is a member with the folder from its name, the rest is skipped by name; each member is first looked up by its SHA-256 over `card_files` and within the drop (decision D30): one whose bytes were read before is left out, not kept, not parsed and never queued for the upload, and named in the answer's `read_before` with the card that holds it and when that card was read; a drop with nothing new makes no card and answers 200 with `id` None and every file under `read_before`; each new member is kept under `cards/<card id>/<folder>/<name>` and parsed with `parse_station_jsonl`; each frame is routed by the LP0 address in its clear header to the bundle's tracker (`trackers_of`: the devices with an `lp0` address, their keys as `Credentials` when the bundle carries them), a frame whose digest was decoded before is `repeated`, else `unwrap_station_frame` and `decode_station_frame` with the device's driver from Protect's registry; a `FrameRefused` or the driver's `ApplicationError` is a `refused` frame with the code and words; an address nobody has is `unknown_address`; a line that is not a frame is `line_error`. Records go in under Protect's canonical key (device, time, kind, the metric or fingerprint) with `INSERT OR IGNORE`, so the counts are new records. The station's reception time counts only when plausible (2020 to tomorrow), as Protect's D324. `card_detail` adds the files, the trackers with their span and the first 100 failures; `positions` is bounded at 5000. `routers/cards.py` is the API (multipart `POST /api/cards`, 409 without a bundle, 422 without a station file). In the interface, `CardsPage` has the drop zone (a folder through `webkitdirectory`, a zip, or dragged files; the relative path travels as the file name) and the list; `CardPage` the counts, the trackers, the positions on `OfflineMap` (which now takes `points` and draws a track per tracker and its fixes), the failures and the files.

## The shell and the pages (decision D13)

## The project map and the trackers (phase 2 F3)

## The upload (decision D2, phase 2 F4)

`card_files` carries the upload's state per file (`upload_status`: pending, uploaded, duplicate, refused, failed; `upload_answer`, `uploaded_at`, `attempts`, `log_file_id`), added to an existing database by `CardStore._migrate`. `protect_go/uploads.py`'s `run_uploads` takes the pending and failed files of one card or all (`pending_files`, oldest card first), posts each as `file` to the station's `POST /api/v1/devices/{station_device_id}/offload-files` with the sign-in's token, and settles the answer (`_settle`): 201 with a file row is `uploaded` (the log file id kept), 201 with the one member skipped is `duplicate` when the member carries `duplicate` (Protect's decision D353) or its reason says "uploaded before" (an older server), else `refused` with the reason, a 422 whose words say "uploaded before" is `duplicate` too (servers before D353), another 422 is `refused` with the words, 401 and 403 mark the file `failed` and stop the run with the way out named (sign in again; the account needs device control in the project), a transport error marks it `failed` and stops the run too. A card whose `station_device_id` is empty (the project knew no station with that EUI when the bundle was loaded) is left pending with the word to make the station on the Offload page and load the project again. `routers/uploads.py`: `GET /api/uploads` (per card and the totals), `POST /api/uploads/run {card_id?}`. The interface: `pages/UploadPage.tsx`; the first screen's Upload button carries the waiting count.

## The offline map (decisions D4 and D32)

`protect_go/routers/map.py`: one map per project, `maps/<project id>.pmtiles` in the data folder with `maps/<project id>.json` beside it (project, build, digest, the bounds and zoom read from the PMTiles header with the `pmtiles` package); the one `map.pmtiles` of versions before moves under the project its `map.json` names at start (`migrate_legacy_map`, called by `create_app`). `POST /api/map/fetch {project_id, project_name}` calls the server's `GET /projects/{id}/field-bundle/map` with the token; a 200 is streamed to the project's file (through a `.part` file); a 404 or 202 makes Protect Go `POST` for the map and keep the server's state in words (`app.state.map_words` per project, which `GET /api/map` answers as `server_state` until the map comes); 401 and 403 say the sign-in expired. `GET /api/map[?project_id]` is the loaded project's state on the laptop; `GET /api/map/{project id}/tiles.pmtiles` serves a project's file with `Range` (206, `Content-Range`, 416 beyond the end), which the pmtiles protocol of MapLibre needs, and 404 without the map (`GET /api/map/tiles.pmtiles`, the loaded project's, is the address of before v0.17.1); one address per project because MapLibre's pmtiles reader caches an archive, its header and directories, by address, so a switch between projects kept the old tiles until the page was reloaded (Tim, 2026-10-24): `tilesUrl(projectId)` and `offlineStyle(flavour, projectId)` in `components/map/useMap.ts`, `useMap(..., projectId)` rebuilding the style on a change with `setStyle(..., {diff: false})` (a diff is applied without `style.load`, so `ready` never came back and nothing was drawn again; v0.17.2), a map waiting for its project (`projectId` undefined until `GET /api/map` answered) and applying a project that changed while its first style loaded once `ready` comes (`applied` against the wanted pair, v0.17.3: a switch from another page mounted the Overview mid-switch), the Overview's map, the explorer's map and `OfflineMap` reading the project id from `GET /api/map` (Tim, 2026-10-24: the LP0 demo project's tiles of West Africa stayed under the real project's station in the Netherlands, whose map the server was still cutting at the load). The connection probe (`_follow_the_project` in `routers/setup.py`) fetches the loaded project's map while it is missing, once every `REVISION_CHECK_EVERY`, and answers `map_updated_at` when it came, on which the shell refreshes the maps; `components/OverviewMap.tsx` shows the server's words and "Fetch the map now" meanwhile. `GET /api/projects` lists the account's projects from the server for the picker. In the interface, `components/OfflineMap.tsx` registers the pmtiles protocol once, builds the style from `@protomaps/basemaps` (`layers("protomaps", namedFlavor("light"|"dark"), {lang: "en"})`) with glyphs and sprites from `public/map/` (the ranges and licence listed in its README), fits the map's bounds and credits OpenStreetMap and Protomaps. Tests: `tests/test_map.py` against a mock server (the fetch, the ranges, the move of the old file, the probe fetching a map the server was still cutting), `MapPage.test.tsx` with the map component mocked.

## The setup (decision D7)

`protect_go/store.py` keeps `settings.json` in the data folder (mode 600): the server, its version, the account's email, Protect's token and its expiry read from the token's `exp`; never the password. `protect_go/protect.py` talks to the server: `probe_version` (`GET /api/version`, anything else is "not a Protect server"), `sign_in` (`POST /api/v1/auth/login` form-encoded, then `GET /api/v1/users/me`, then `_lengthen`: the hour's token mints a one-time code at `POST /auth/go-handoff` and exchanges it for the weeks-long token of Protect's D333, an older server leaving the hour's). `routers/setup.py`: `GET /api/setup`, `GET /api/setup/connection` (decision D18: one probe of the server's version and, signed in, one read of the account; `online`, `checked_at`, `protect_version`, `account_ok`, `error`; 409 with no server; the Server page and the top bar's dot poll it every minute), `PUT /api/setup/server` (a new server ends the session), `POST /api/session`, `POST /api/session/handoff {server_url, code}` (D15: the server kept once it answers, the code exchanged at Protect's `POST /auth/go-handoff/exchange` for a 30-day token, a used or expired code is 401 with the way out named), `DELETE /api/session`. The tests hand `app.state.http_transport` an `httpx.MockTransport`. The interface gates on the setup (`App.tsx`): no server shows `SetupPage` alone, which reads `?server=` from the protocol link and, with `&code=`, signs in by itself through the handoff and lands on Overview; with a server, `/setup` and `/sign-in` both show `pages/ServerPage.tsx` (decision D18): the connected server with its version, the live state with the time of the last check and Check now, and the account on it (signed in as whom until when, Sign out, Sign in as someone else) or the sign-in form; Another server brings the server form back. `SetupPage` and `SignInPage` are the forms, embedded with an `onCancel`; `LoadSection` from `pages/LoadPage.tsx` is the project's loading at the foot of the page (`/load` shows the Server page too). The sidebar's Settings section has Server alone; Account and Load a project went into it.

## Commands

```bash
scripts/dev.sh hooks            # once per clone
uv sync --all-groups
(cd frontend && npm ci)
(cd electron && npm ci)         # on npm 11, if node_modules/electron/dist is missing: node node_modules/electron/install.js

scripts/dev.sh docs             # mkdocs --strict and the docs check
scripts/dev.sh run              # the server with the built interface on http://127.0.0.1:18090
(cd frontend && npm run dev)    # live reload on http://127.0.0.1:5173, /api proxied to the server
scripts/dev.sh desktop          # the Electron shell against .venv and the built interface
scripts/dev.sh freeze           # the frozen backend in dist/backend/, as the installers carry it
scripts/dev.sh bump-protect     # move the Protect pin to the newest main and prove the decoding
```

Under WSL the shell runs through WSLg; `--no-sandbox` may be needed there. A terminal inside VS Code sets `ELECTRON_RUN_AS_NODE=1`, which makes the Electron binary run as plain Node and fail on `ipcMain`; `scripts/dev.sh desktop` unsets it. `PROTECT_GO_DATA_DIR` and `PROTECT_GO_PORT` point a run elsewhere. With `--remote-debugging-port=9333`, `curl http://127.0.0.1:9333/json` lists the page the window loaded.

After adding UI strings: `cd frontend && npm run i18n:extract`, then write the Dutch lines in `src/locales/nl/translation.json` by hand, appended.
